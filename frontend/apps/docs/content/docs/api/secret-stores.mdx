# Secret Stores API

Secret stores define how Wardn connects to secret providers — SOPS key providers, External Secrets stores, and Vault instances. Credentials are encrypted at rest and never returned by the API.

## Endpoints

### List Secret Stores

```http
GET /api/v1/secret-stores
```

**Response — 200 OK**

```json
{
  "items": [
    {
      "id": "sts_01H8X2K3M4N5P6Q7R8S9T0U1VA",
      "name": "production-sops",
      "type": "sops",
      "provider": "aws-kms",
      "status": "Connected",
      "lastTestedAt": "2024-01-15T10:00:00Z",
      "config": {
        "keyArn": "arn:aws:kms:us-east-1:123456789:key/abcd-1234",
        "region": "us-east-1"
      }
    },
    {
      "id": "sts_01H8X2K3M4N5P6Q7R8S9T0U1VB",
      "name": "staging-vault",
      "type": "vault",
      "provider": "vault",
      "status": "Connected",
      "lastTestedAt": "2024-01-15T09:45:00Z",
      "config": {
        "address": "https://vault.example.com:8200",
        "authMethod": "kubernetes"
      }
    }
  ]
}
```

<Callout type="warn">
  Credentials (KMS keys, tokens, private keys) are write-only. They are never included in API responses.
</Callout>

### Create Secret Store

```http
POST /api/v1/secret-stores
```

Requires the `admin` role.

**SOPS with AWS KMS**

```json
{
  "name": "production-sops",
  "type": "sops",
  "provider": "aws-kms",
  "config": {
    "keyArn": "arn:aws:kms:us-east-1:123456789:key/abcd-1234",
    "region": "us-east-1"
  },
  "credentials": {
    "accessKeyId": "AKIA...",
    "secretAccessKey": "..."
  }
}
```

**SOPS with age**

```json
{
  "name": "dev-age",
  "type": "sops",
  "provider": "age",
  "credentials": {
    "privateKey": "AGE-SECRET-KEY-1XYZ..."
  }
}
```

**Vault**

```json
{
  "name": "production-vault",
  "type": "vault",
  "provider": "vault",
  "config": {
    "address": "https://vault.example.com:8200",
    "authMethod": "kubernetes",
    "kubernetesRole": "wardn-operator",
    "mountPath": "secret"
  }
}
```

**Response — 201 Created**

```json
{
  "id": "sts_01H8X2K3M4N5P6Q7R8S9T0U1VA",
  "name": "production-sops",
  "type": "sops",
  "provider": "aws-kms",
  "status": "Connected"
}
```

Wardn immediately tests the connection. If the test fails, the store is created with `status: "Error"` and the error is included.

**Errors**

| Status | Description |
|--------|-------------|
| `400` | Invalid config for the provider type |
| `403` | Insufficient permissions |
| `409` | Store name already exists |

### Test Secret Store

```http
POST /api/v1/secret-stores/{id}/test
```

**Response — 200 OK**

```json
{
  "status": "Connected",
  "latency": "120ms",
  "details": "Successfully encrypted and decrypted a test value"
}
```

For SOPS stores, the test performs an actual encrypt/decrypt round-trip. For Vault, it authenticates and reads a test path.

---

### Update Secret Store

```http
PATCH /api/v1/secret-stores/{id}
```

**Request Body**

```json
{
  "config": {
    "keyArn": "arn:aws:kms:us-east-1:123456789:key/new-key",
    "region": "us-east-1"
  }
}
```

To rotate credentials, include the new `credentials` object. Omitted fields are unchanged.

**Response — 200 OK**

---

### Delete Secret Store

```http
DELETE /api/v1/secret-stores/{id}
```

**Response — 204 No Content**

Returns `409 Conflict` if applications reference this store.

## Store Types

| Type | Provider | Credentials Required |
|------|----------|---------------------|
| `sops` | `aws-kms` | AWS access key + secret (or IRSA) |
| `sops` | `gcp-kms` | GCP service account JSON |
| `sops` | `age` | age private key |
| `sops` | `vault-transit` | Vault token |
| `sops` | `pgp` | PGP private key |
| `vault` | `vault` | Kubernetes JWT / AppRole / token |
| `eso` | (various) | Managed by ESO itself |

## Security

- **Encrypted at rest** — store credentials are encrypted with the server's master key
- **Write-only** — credentials are never returned in API responses
- **Audited** — all store operations are recorded in the audit log
- **Scoped** — stores can be scoped to specific projects (planned)
