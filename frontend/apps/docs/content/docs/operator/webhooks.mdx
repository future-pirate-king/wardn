# Webhooks

The operator runs an HTTP webhook receiver alongside the controller. Git providers push events to it, and matching `GitApplication`s are reconciled immediately — no waiting for the 60-second poll.

## Receiver Endpoints

| Endpoint | Provider | Status |
|----------|----------|--------|
| `POST /webhook/github` | GitHub | ✅ Supported |
| `POST /webhook/gitlab` | GitLab | 🚧 Stub |

Default port: `8082`.

## GitHub Push Flow

```
GitHub push
    │
    ▼
POST /webhook/github
    │
    ├─ 1. Parse payload (X-GitHub-Event: push)
    ├─ 2. Extract repo URL + branch + commits
    ├─ 3. List GitApplications
    ├─ 4. Match by repoURL + branch
    ├─ 5. Check webhook.enabled
    └─ 6. Annotate matching apps
              │
              ▼
        Reconcile triggered immediately
```

## Payload Handling

The receiver parses GitHub push payloads:

```json
{
  "repository": {
    "clone_url": "https://github.com/myorg/my-app.git",
    "full_name": "myorg/my-app"
  },
  "ref": "refs/heads/main",
  "after": "a1b2c3d4e5f6...",
  "pusher": { "name": "developer" }
}
```

Matching logic:

1. **Repo match** — `repository.clone_url` matches `spec.repoURL` (normalized: trailing `.git` stripped)
2. **Branch match** — `ref` (`refs/heads/main`) matches `spec.branch`
3. **Webhook enabled** — `spec.webhook.enabled` must be `true`

Matching applications are annotated:

```yaml
metadata:
  annotations:
    wardn.io/sync-triggered-at: "2024-01-15T10:30:00Z"
```

The controller watches for this annotation and reconciles immediately.

## Signature Validation

<Callout type="warn">
  Signature validation is partially implemented. Ensure your webhook receiver is not publicly exposed without validation.
</Callout>

GitHub signs payloads with `X-Hub-Signature-256` using the webhook secret. Full validation flow:

1. Read the secret from the app's `spec.webhook.secretRef`
2. Compute HMAC-SHA256 of the payload body
3. Compare with the `X-Hub-Signature-256` header
4. Reject with `401 Unauthorized` on mismatch

## Rate Limiting

Webhook floods are rate-limited per source:

- Default: 100 requests/minute per source IP
- Exceeding the limit returns `429 Too Many Requests`
- Rate limit state is kept in memory (per-pod)

## Exposing the Receiver

### Ingress (production)

```yaml
apiVersion: networking.k8s.io/v1
kind: Ingress
metadata:
  name: wardn-webhook
  annotations:
    cert-manager.io/cluster-issuer: letsencrypt
spec:
  tls:
    - hosts: [webhook.wardn.example.com]
  rules:
    - host: webhook.wardn.example.com
      http:
        paths:
          - path: /webhook
            pathType: Prefix
            backend:
              service:
                name: wardn-operator
                port:
                  number: 8082
```

### LoadBalancer / NodePort

```sh
kubectl -n wardn-system expose deployment wardn-operator \
  --name wardn-webhook --port 8082
```

## Testing

Send a test payload:

```sh
curl -X POST http://localhost:8082/webhook/github \
  -H "Content-Type: application/json" \
  -H "X-GitHub-Event: push" \
  -d '{
    "repository": { "clone_url": "https://github.com/myorg/my-app.git" },
    "ref": "refs/heads/main",
    "after": "abc123"
  }'
```

Response:

```json
{ "matched": 1, "apps": ["default/my-app"] }
```

## GitLab Support

GitLab push events are currently a stub. The endpoint exists but full payload parsing and matching are not implemented. Track progress in the [roadmap](/reference/roadmap).
