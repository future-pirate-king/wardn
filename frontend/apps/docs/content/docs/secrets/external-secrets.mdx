# External Secrets Operator

The [External Secrets Operator](https://external-secrets.io) (ESO) syncs secrets from external providers into Kubernetes Secrets. Wardn watches ESO custom resources and surfaces their sync status in the application UI — so you can see secret health alongside app health.

## Supported Providers

| Provider | Status |
|----------|--------|
| AWS Secrets Manager | ✅ Supported |
| GCP Secret Manager | ✅ Supported |
| HashiCorp Vault | ✅ Supported |
| Azure Key Vault | ✅ Supported |
| Kubernetes (cluster-to-cluster) | ✅ Supported |

## How It Works

```
┌──────────────┐     ┌─────────────┐     ┌───────────────┐
│ AWS Secrets  │◀────│  External   │────▶│   K8s Secret  │
│  Manager     │sync │  Secrets    │create│  (my-secret) │
└──────────────┘     │  Operator   │     └───────────────┘
                     └──────▲──────┘
                            │ watches
                     ┌──────┴──────┐     ┌───────────────┐
                     │ExternalSecret│◀────│    Wardn      │
                     │    CRD      │watch│   (status)    │
                     └─────────────┘     └───────────────┘
```

1. **You commit** an `ExternalSecret` CRD to Git (safe — contains only references, not values)
2. **ESO** fetches the actual secret values from the provider
3. **ESO creates** a regular Kubernetes Secret
4. **Wardn** watches the `ExternalSecret` status and surfaces it in the UI

## Tutorial: AWS Secrets Manager

<Steps>

### Step 1: Install ESO

```sh
helm repo add external-secrets https://charts.external-secrets.io
helm install external-secrets \
  external-secrets/external-secrets \
  -n external-secrets \
  --create-namespace
```

### Step 2: Create a Secret in AWS

```sh
aws secretsmanager create-secret \
  --name prod/my-app/db-password \
  --secret-string "super-secret-password"
```

### Step 3: Create a SecretStore

```yaml
# secret-store.yaml
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: aws-secrets-manager
  namespace: default
spec:
  provider:
    aws:
      service: SecretsManager
      region: us-east-1
      auth:
        jwt:
          serviceAccountRef:
            name: external-secrets-sa
```

### Step 4: Create an ExternalSecret

```yaml
# external-secret.yaml
apiVersion: external-secrets.io/v1beta1
kind: ExternalSecret
metadata:
  name: db-credentials
  namespace: default
spec:
  refreshInterval: 1h
  secretStoreRef:
    name: aws-secrets-manager
    kind: SecretStore
  target:
    name: db-credentials       # name of the created K8s Secret
    creationPolicy: Owner
  data:
    - secretKey: password      # key in the K8s Secret
      remoteRef:
        key: prod/my-app/db-password   # key in AWS
```

### Step 5: Commit and Deploy

```sh
git add secret-store.yaml external-secret.yaml
git commit -m "Add ESO secret store and external secret"
git push
```

Wardn syncs these manifests like any other. ESO then creates the actual `db-credentials` Secret.

### Step 6: View Status in Wardn

The application detail page shows:

- **ESO Secret** — sync status (`Ready`, `SecretSyncedError`, etc.)
- **Last refresh** — when ESO last synced from AWS
- **Provider** — which secret store the value came from

</Steps>

## ESO Status in Wardn

Wardn maps ESO conditions to health status:

| ESO Condition | Wardn Health |
|---------------|-------------|
| `Ready` (SecretSynced) | `Healthy` |
| `SecretSyncedError` | `Degraded` |
| Missing/Progressing | `Progressing` |

This means a broken secret sync degrades your application's health — you'll see it in the dashboard, and notifications fire if configured.

## Referencing ESO Secrets in Your App

Your Deployment references the created Secret like any other:

```yaml
apiVersion: apps/v1
kind: Deployment
metadata:
  name: my-app
spec:
  template:
    spec:
      containers:
        - name: app
          envFrom:
            - secretRef:
                name: db-credentials   # created by ESO
```

## Multiple Providers

You can mix providers — different `SecretStore`s for different namespaces or environments:

```yaml
# Staging uses GCP
apiVersion: external-secrets.io/v1beta1
kind: SecretStore
metadata:
  name: gcp-secret-manager
spec:
  provider:
    gcpsm:
      projectID: my-staging-project
```

## Troubleshooting

### ExternalSecret Shows `SecretSyncedError`

```sh
kubectl describe externalsecret db-credentials
```

Common causes:
- **IAM permissions** — the ESO service account lacks `secretsmanager:GetSecretValue`
- **Wrong key** — the `remoteRef.key` doesn't exist in the provider
- **Store misconfigured** — region, project ID, or auth is incorrect

### Secret Not Created

Check ESO operator logs:

```sh
kubectl logs -n external-secrets deployment/external-secrets
```

## SOPS vs ESO

| Aspect | SOPS | ESO |
|--------|------|-----|
| Secret values in Git | Encrypted | No (references only) |
| Extra operator required | No | Yes |
| Rotation | Re-encrypt + commit | Automatic (refreshInterval) |
| Central management | No (per-file) | Yes (provider-side) |

Use **SOPS** when you want secrets versioned with your code. Use **ESO** when secrets live in a dedicated manager and you want automatic rotation.
