# Server

The Wardn server is the central API layer. It handles authentication, RBAC, cluster management, sync orchestration, real-time updates, and audit logging. Equivalent to ArgoCD's `argocd-server` but with built-in auth (no separate Dex).

## Architecture

| Component | Technology |
|-----------|-----------|
| Router | `chi/v5` |
| Database | Postgres 18 (`jackc/pgx/v5`) |
| Cache | Redis 8 (`redis/go-redis/v9`) |
| Auth | Local users (bcrypt) + OIDC (`coreos/go-oidc/v3`) |
| Sessions | Redis-backed with 24h TTL |
| Real-time | SSE via Redis pub/sub |

```
┌──────────┐     ┌──────────┐     ┌──────────┐
│ Frontend │────▶│  Server  │────▶│ Postgres │
│ (Next.js)│     │ (Go API) │     │ (state)  │
└──────────┘     └────┬─────┘     └──────────┘
                      │
                      ├──▶ Redis (cache + pubsub + sessions)
                      ├──▶ Operator (k8s controller)
                      └──▶ Webhook receiver
```

## Configuration

All configuration is via environment variables.

| Variable | Default | Description |
|----------|---------|-------------|
| `HTTP_ADDR` | `:8080` | HTTP listen address |
| `POSTGRES_URL` | `postgres://wardn:wardn@localhost:5432/wardn?sslmode=disable` | Postgres connection string |
| `REDIS_URL` | `redis://localhost:6379/0` | Redis connection string |
| `JWT_SECRET` | — | **Required.** Secret for signing session tokens |
| `OIDC_PROVIDER_URL` | — | OIDC provider URL (optional) |
| `OIDC_CLIENT_ID` | — | OIDC client ID (optional) |
| `OIDC_CLIENT_SECRET` | — | OIDC client secret (optional) |
| `OPERATOR_ADDR` | `localhost:8081` | Operator gRPC address |

<Callout type="warn">
  `JWT_SECRET` must be set to a strong random value in production. Never use the default or leave it empty.
</Callout>

## API Endpoints

### Health

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/v1/health` | None | Health check |

### Authentication

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `POST` | `/api/v1/auth/register` | None | Register a new user |
| `POST` | `/api/v1/auth/login` | None | Login and create session |
| `POST` | `/api/v1/auth/logout` | Session | Destroy session |
| `GET` | `/api/v1/auth/me` | Session | Get current user |

<Callout type="info">
  For detailed auth API examples (request/response bodies), see the [Authentication API](/api/authentication) page.
</Callout>

### Applications

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/v1/apps` | Session | List all GitApplications |
| `GET` | `/api/v1/apps/{namespace}/{name}` | Session | Get a specific application |
| `POST` | `/api/v1/apps/{namespace}/{name}/sync` | Session+Sync | Trigger manual sync |
| `GET` | `/api/v1/apps/{namespace}/{name}/history` | Session | Get sync history |

### Projects

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/v1/projects` | Session | List projects |
| `POST` | `/api/v1/projects` | Session+Admin | Create a project |
| `GET` | `/api/v1/projects/{id}` | Session | Get a project |

### Clusters

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/v1/clusters` | Session | List registered clusters |
| `POST` | `/api/v1/clusters` | Session+Admin | Register a new cluster |

### Audit

| Method | Path | Auth | Description |
|--------|------|------|-------------|
| `GET` | `/api/v1/audit` | Session | List audit log entries |

## RBAC

Wardn uses project-scoped RBAC with three roles:

| Role | Permissions |
|------|------------|
| `read` | View apps, sync status, health |
| `sync` | All read permissions + trigger syncs |
| `admin` | All sync permissions + manage project members, delete apps |

Roles are stored in the `project_users` table and enforced via middleware on every API request.

<Callout type="info">
  For more details on RBAC configuration and management, see the [RBAC](/operator/rbac) page.
</Callout>

## Database Schema

The server auto-migrates on startup. Core tables:

| Table | Purpose |
|-------|---------|
| `users` | Local user accounts with bcrypt-hashed passwords |
| `projects` | Logical grouping with RBAC boundary |
| `project_users` | Maps users to projects with roles |
| `clusters` | Registered Kubernetes clusters |
| `repo_creds` | Git repository credentials (SSH, HTTPS, GitHub App) |
| `secret_stores` | SOPS, ESO, and Vault integration configs |
| `sync_history` | Revision tracking for rollback |
| `audit_log` | Who did what, when |

### Redis Keys

```
cache:repo:{repo_url}:manifests     — parsed manifests cache
cache:repo:{repo_url}:revision      — last known revision
cache:health:{app_name}:{namespace} — health check results
cache:secrets:{store_id}            — secret store connectivity status
session:{session_id}                — user session data
pubsub:app:{namespace}:{name}       — status change channel for SSE
ratelimit:webhook:{source}          — webhook rate limiting
```

## Running Locally

<Tabs>
  <Tab value="docker-compose" label="Docker Compose">

  ```sh
  docker compose up -d
  ```

  This starts Postgres, Redis, server, operator, and all frontend apps.

  </Tab>
  <Tab value="manual" label="Manual">

  ```sh
  # Start Postgres and Redis
  docker run -d --name wardn-pg -p 5432:5432 \
    -e POSTGRES_USER=wardn -e POSTGRES_PASSWORD=wardn -e POSTGRES_DB=wardn \
    postgres:18-alpine

  docker run -d --name wardn-redis -p 6379:6379 redis:8-alpine

  # Start the server
  cd server
  export JWT_SECRET="dev-secret"
  export POSTGRES_URL="postgres://wardn:wardn@localhost:5432/wardn?sslmode=disable"
  export REDIS_URL="redis://localhost:6379/0"
  go run ./cmd/server
  ```

  </Tab>
</Tabs>
