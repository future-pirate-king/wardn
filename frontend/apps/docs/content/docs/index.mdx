# Wardn

Wardn is a **GitOps-first continuous delivery platform** for Kubernetes. It synchronizes cluster state from Git repositories — handling manifest parsing, server-side apply, health checks, and notifications — with a focus on operational simplicity.

> **Enterprise features, not enterprise complexity.** Three components. Built-in auth. A UI that doesn't require a YAML editor to create an application.

## How It Works

```
┌────────────┐     ┌────────────┐     ┌─────────────────┐
│  Git Repo  │────▶│  Operator  │────▶│  K8s Cluster    │
│ (source of │     │ (reconcile)│     │ (target state)  │
│   truth)   │     └─────┬──────┘     └─────────────────┘
└────────────┘           │
                         ├──▶ Parse manifests (Raw / Helm / Kustomize)
                         ├──▶ Server-side apply with pruning
                         ├──▶ Health checks per resource
                         ├──▶ Notifications (Slack, Teams, Email)
                         └──▶ Status updates → Server → UI (SSE)
```

## Why Wardn?

| Feature | Wardn | ArgoCD | Flux |
|---------|-------|--------|------|
| **Components** | 3 (server, operator, frontend) | 5+ (server, repo-server, controller, dex, redis) | 1 (operator only) |
| **Built-in UI** | Yes — full dashboard with wizard | Yes — but cluttered | No |
| **Auth** | Built-in (local + OIDC) | Separate Dex component | None |
| **Secret management** | SOPS + ESO + Vault with unified UI | SOPS only, no UI | SOPS only |
| **RBAC** | Project-scoped, UI-managed | CAS config in YAML | None |
| **Installation** | One Helm chart | Multi-chart setup | kubectl apply |

## Key Features

### Core GitOps

- **Git synchronization** — clone, pull, and track revisions automatically with commit-level granularity
- **Manifest parsing** — raw YAML/JSON, Helm, and Kustomize support
- **Server-side apply** — declarative resource management with automatic pruning
- **Health checks** — per-resource health status aggregation with configurable probes
- **Sync policies** — automated sync, prune, and self-heal
- **Multi-cluster** — register and deploy to remote clusters from a single control plane

### Platform & Security

- **Authentication** — local users (bcrypt) + OIDC (Google, GitHub, Keycloak)
- **RBAC** — project-scoped permissions with read, sync, and admin roles
- **Audit logging** — complete activity trail for compliance
- **Real-time updates** — SSE via Redis pub/sub for live sync status
- **Sync history & rollback** — revision tracking with one-click rollback

### Secret Management

- **SOPS** — decrypt at apply time (AWS KMS, GCP KMS, age, Vault Transit)
- **External Secrets Operator** — watch CRDs and surface sync status in the UI
- **Vault Direct** — optional direct Vault integration
- **Unified UI** — all secret sources visible in a single interface

### Notifications & Webhooks

- **Slack, Teams, Email** — notifications on sync success, failure, and health degradation
- **GitHub & GitLab** — webhook triggers with signature validation

## Quick Start

```sh
git clone https://github.com/future-pirate-king/wardn.git
cd wardn
docker compose up -d
```

The platform dashboard is available at `http://localhost:3002`.
